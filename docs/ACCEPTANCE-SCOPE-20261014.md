### 本轮发现与处理

- **已关闭：旧项目假成功入口。** 原 `projects-pages.tsx` 的角色变体只显示“已加入生成队列”，导出设置只显示“已保存”，角色/场景也含固定演示内容。当前两条 `app/projects/[projectId]` 路由不再导入该组件，旧任意 section 均进入真实画布；未对大型遗留文件作表面修改。
- **已关闭：短剧大纲错误端点。** 原 `drama-page.tsx` 直接调用后端不存在的 `/api/drama/analyze`，不在旧 API wrapper 注册测试范围。当前 `/drama` 索引转入真实项目创建流程，路由树不再导入该页面。
- **已关闭：邀请落地标签错误。** 当前入口直接去 `/register`，并安全处理非法邀请码；合法邀请码仍传给注册契约。
- **已关闭：支付配置编辑器不匹配。** 原页面查找不存在的 `epay`，现已选择当前 `manual` 定义，读取并提交 enabled/instructions；校验服务端同字段、启用状态与 readiness 确认后才提示保存成功。没有把人工收款配置保存当成订单到账，也不谎称自动回调可用。
- **已关闭：购买政策位置不一致与草稿发布死锁。** 当前独立后端把管理端顶层字段映射到 `site.commercePolicy` 并返回一致别名；两个位置同时写入会被拒绝。编辑器以“已保存字段完整性”允许首次发布，当前已发布标记仍要求真实 published 状态。没有 `commerce.manage` 的管理员可查看政策，但字段和写操作禁用；后端权限没有为界面兼容而放宽。
