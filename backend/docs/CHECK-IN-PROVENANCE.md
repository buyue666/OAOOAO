# Manual account check-in

Independently implemented from the OAOOAO product request and this repository's `SPECIFICATION.md`, `src/core.ts`, `src/wallet.ts`, authentication/settings contracts and disposable PostgreSQL test fixtures. No third-party application implementation or assets were consulted.

The initial manual check-in contribution granted permanent wallet credits once per account per Shanghai calendar day. The subsequent credit-batch implementation supports configured reward amounts and validity per effective membership, with zero validity meaning permanent; its provenance is recorded in [CORE-PROVENANCE.md](CORE-PROVENANCE.md#2026-10-14--independently-implemented-check-in-credit-batches). Check-in is disabled by default, with a default reward of 10. The existing UTC daily allowance remains a separate mechanism. A unique account/date claim, wallet adjustment, reward/validity snapshot and audit write share one transaction. Repeat requests return the current balance without granting again. Configuration uses the existing commerce management permission. The optional internal test clock is never exposed to request input. The original author's no-third-party-input statement above describes that contribution, not all later contributors or the complete application.
